# Anidle

Game tebak anime harian untuk saya dan teman-teman. Pool berisi anime *completed* dari list MAL pemain dan anime populer di MAL (≥ 50 rb member), masing-masing dengan difficulty easy/medium/hard. Rencana lengkap: [PLAN.md](PLAN.md).

Status: **M1–M7 selesai**: pipeline data, mode Anidle, media di R2 + mode Opening/Ending, mode Karakter, leaderboard + riwayat + share, mode Screenshot + review media admin, pipeline mingguan di GitHub Actions. Live di https://anidle.velvetaco.dev.

## Akun

- **Tanpa akun**: langsung main. Progres disimpan di browser lewat cookie anonim `anidle_anon`.
- **Akun Anidle** (username + password, hash scrypt): progres ikut ke semua perangkat. Saat daftar/masuk, progres anonim di browser itu dipindah ke akun.
- **Masuk dengan MAL** ("Continue with MyAnimeList" di `/masuk`, lewat OAuth MAL): kalau akun MAL itu sudah terhubung ke akun Anidle, langsung masuk ke akun itu (dicocokkan lewat **id user MAL** `account.mal_id`, bukan username: username MAL bisa berganti pemilik; kalau pemiliknya ganti nama, akunnya ikut nama baru, dan link lama yang memegang nama itu dilepas); kalau belum, dibuatkan akun Anidle tanpa password bernama username MAL (karakter selain huruf/angka/`_` jadi `_`, diberi akhiran acak kalau sudah dipakai). Akun seperti ini hanya bisa masuk lewat MAL, jadi MAL-nya tidak bisa di-unlink. List completed langsung di-sync tiap kali masuk (kecuali baru di-sync < 10 menit lalu).
- **Hubungkan MAL** (untuk akun username + password): membuka pool dari list completed (`teman`, `bareng`, `saya`). Lewat OAuth MAL, jadi list private ikut terbaca. Puzzle harian, pool `semua`, dan `populer` terbuka untuk semua orang.
- **My MAL list** (`/mylist`, hanya akun yang menghubungkan MAL; muncul di sidebar bagian Community): seluruh list anime MAL pemain dibaca langsung dari MAL dengan token-nya (entri private ikut), tidak disimpan di Turso (`GET /api/mal/list`, `server/mallist.ts`; dipakai ulang 2 menit per instance, tombol Refresh = `?fresh=1`, batas 10 request/menit per IP). Tab Watching / Completed / On-Hold / Dropped / Plan to Watch dengan jumlah; tiap tab punya pencarian, filter Type, Genre, dan Airing, serta sort sendiri (Last updated, Title, My score, MAL score, Year, Progress; pilihan sort per tab diingat browser). Tab aktif ada di URL (`?status=`).
- Pool bersama (harian, `semua`, `teman`, `bareng`) hanya memakai list `POOL_USERS`. Akun lain yang menghubungkan MAL hanya dapat pool `saya` miliknya, jadi orang asing tidak bisa mengubah puzzle harian. List mereka juga tidak menambah katalog: pool `saya` memakai judul yang sudah ada (hanya list `POOL_USERS` dan `popular` yang di-enrich).
- **Sinkron ulang** (`POST /api/sync`): paling sering sekali per 10 menit per akun (`SYNC_COOLDOWN_MS`); hanya selisih list yang ditulis ke `completed`.

## Jalan lokal

Butuh **Node 24 LTS** (`.nvmrc`, `engines: 24.x`; Vercel juga menjalankan 24.x). Pakai patch terbaru, minimal 24.22.1, yang berisi perbaikan keamanan 21 Okt 2026 (termasuk CVE-2026-111497 di decoder Brotli). Update dependency keamanan datang otomatis lewat Dependabot (`.github/dependabot.yml`); cek manual dengan `npm audit`.

```bash
npm install
cp .env.example .env          # isi MAL_CLIENT_ID/SECRET, SESSION_SECRET, TOKEN_ENC_KEY, POOL_USERS
npm run pipeline              # isi database lokal data/anidle.db (±10 menit pertama kali)
npm run dev                   # http://localhost:3000
```

Menghubungkan MAL di lokal butuh App Redirect URL app MAL `http://localhost:3000/oauth/callback` (app playground sudah begitu).

## Pipeline

```bash
npm run pipeline                       # semua step
npm run pipeline -- completed enrich   # step tertentu: genres, completed, popular, enrich, synopsis, franchise, media, characters, nicknames, aliases, screenshots, clips, titles, catalog, daily, cleanup
npm run pipeline -- catalog            # hanya bangun ulang katalog (mis. setelah ambang difficulty berubah)
npm run pipeline -- enrich --refresh   # ambil ulang detail semua judul
npm run pipeline -- enrich --limit=50  # cicil
npm run pipeline -- --turso           # tulis ke Turso: baca .env.turso dulu, lalu .env untuk sisanya
```

| Step | Isi |
| --- | --- |
| `genres` | 78 genre/explicit genre/theme/demographic dari jikan-edge |
| `completed` | List completed setiap `POOL_USERS` dan setiap akun yang menghubungkan MAL. Pakai token MAL-nya kalau ada (list private ikut), kalau tidak lewat Client ID (list publik saja). Hanya selisih yang ditulis; judul baru masuk `enrich_queue` hanya dari list `POOL_USERS` |
| `popular` | Ranking popularitas resmi MAL (`ranking_type=bypopularity`) sampai `members ≥ 50.000`, tanpa Music/CM/PV |
| `enrich` | Detail MAL untuk judul pool bersama (list `POOL_USERS`, `popular`, `enrich_queue`) yang baru / lebih tua dari 30 hari: judul alternatif, cover, tahun, skor, jumlah member, source, studio, genre, relasi, sinopsis. Hentai/Erotica, music/CM/PV, dan judul yang belum tayang ditandai `excluded` (judul belum tayang masuk lagi setelah tayang, pada enrich berikutnya) |
| `synopsis` | Sinopsis MAL (`anime.synopsis`, clue kedua Anidle) untuk show yang di-enrich sebelum sinopsis disimpan; `''` = MAL tidak punya. Setelah itu `enrich` yang menjaganya tetap baru |
| `franchise` | Satu **show** per franchise: season, movie, OVA, recap, side story, dan remake yang terhubung lewat relasi MAL `prequel`/`sequel`/`side_story`/`parent_story`/`summary`/`full_story`/`alternative_version` digabung (mis. Kino no Tabi 2003 + 2017, Fullmetal Alchemist + Brotherhood; spin-off dan alternative setting tetap terpisah). Relasi `other` ikut menggabung kalau extra-nya dinamai seperti show-nya dan keduanya bukan seri TV (`otherIsSameShow` di `shared/franchise.ts`: Kobayashi-san Chi no OO Dragon ke Maid Dragon, NG-shuu Kuroko no Basket; Yu☆Gi☆Oh! GX/Zexal tetap terpisah). Entri paling populer (member MAL terbanyak) jadi entri kanonik (`anime.canonical_id`): hanya entri itu yang ditanya, muncul di autocomplete dan halaman Database, dan member-nya menentukan difficulty. Nama season lain tetap bisa dicari di autocomplete; menebak entri mana pun dari franchise itu benar |
| `media` | Per show (entri kanonik, paling populer dulu): cover MAL → WebP lebar 400 di R2 (`v1/cover/<hash>.webp`, nama = hash isi, cache `immutable`), hasilnya di tabel `anime_media` (`ok` / `missing` / `broken` / `rejected`; `missing`/`broken` dicoba lagi setelah 30 hari, `rejected` (ditolak admin) hanya dengan `--refresh`). Lalu **semua** OP dan ED dari **semua entri MAL** show itu (entri kanonik + season/movie/OVA yang digabung; satu request AnimeThemes per entri) dicatat saja di tabel `anime_theme` per id theme AnimeThemes (URL audio + video terkecil + judul lagu + artis + entri asalnya), tidak diunduh. Difficulty sebuah lagu = difficulty **entri asalnya** (member MAL entri itu), bukan show-nya. Entri yang sudah punya lagu hanya ditanya lagi dengan `--refresh`, entri tanpa lagu setelah 30 hari (`anime.themes_at`); lagu yang tidak lagi ada di AnimeThemes ditandai `missing` (tidak ditanya lagi, tapi puzzle lama tetap menemukan lagunya), status `rejected` dari admin dan klipnya tetap (klip dibuang kalau audionya berubah). Gangguan jaringan/R2/DB tidak menandai apa pun, judul/entrinya dicoba lagi di run berikutnya. Butuh `R2_*` di `.env`; ffmpeg dari `ffmpeg-static` |
| `characters` | Per show, **semua** karakter dengan ≥ 50 favorit MAL dari **semua entri** show itu (entri kanonik + season/movie/OVA yang digabung; satu request jikan-edge per entri, karakter yang muncul di beberapa entri disimpan sekali dengan favorit terbanyak, role Main kalau salah satu entri bilang Main), tanpa gambar placeholder → WebP lebar 300 di `v1/char/<hash>.webp`, tabel `anime_character` di bawah id show (slot 0 = paling terkenal). Difficulty karakter dari favorit MAL karakter itu sendiri: easy ≥ 5.000, medium 500–4.999, hard 50–499; di bawah 50 tidak disimpan (dulu 100, tapi 46 show medium jadi tanpa karakter sama sekali; karakter terkenalnya hanya 82–99 favorit). Portrait, nickname, alias, dan `details_at` yang sudah ada untuk karakter itu (di show mana pun) dipakai lagi, jadi hanya karakter baru yang diunduh. Show tanpa satu pun karakter seperti itu `missing` (tidak ditanya; baris lamanya tetap, supaya puzzle lama utuh); satu karakter sudah cukup, karena Character mode menanyakan satu karakter per show dan clue Anidle menampilkan maksimal dua. Entri kanonik gagal diambil = show dilewati tanpa ditandai; entri gabungan yang gagal dilewati saja (karakter tersimpan show itu tetap, dicoba lagi di run berikutnya). Karakter tiap entri dicatat di `character_show` per id entri: Character mode menerima show mana pun tempat karakter itu muncul |
| `nicknames` | Nickname **romaji** semua karakter tersimpan (paling terkenal dulu) dari jikan-edge `/v1/characters/{id}` (kolom `nicknames`, satu request per karakter), supaya karakter juga bisa dicari lewat alias di autocomplete. Nickname kana/kanji/hangul dibuang (`isRomaji`): nama karakter dijawab dalam romaji saja |
| `aliases` | Nama alternatif dari **AniList** (kolom `aliases`; mis. Bentham: "Mr. 2", "Bon Clay", "Bon-chan"; Enji Todoroki: "Endeavor"), tanpa nama spoiler (AniList memisahkannya) dan tanpa bagian kanji/kana dalam kurung. Per show (paling populer dulu): cast AniList dari entri-entri show itu (50 per request, paling terkenal dulu, maks 8 request per show) dicocokkan ke karakter tersimpan lewat nama (`sameCharacterName`: kata-kata nama MAL "Monkey D., Luffy" vs AniList "Luffy Monkey"; nama satu kata harus sama persis, nama yang cocok ke dua karakter dilewati). `anime.aliases_at` mencatat show yang sudah ditanya; ulangi dengan `--refresh`. Autocomplete, jawaban Character, dan halaman detail memakai gabungan nickname MAL + alias AniList (`characterAliases`) |
| `screenshots` | 3 frame dari video lagu show itu yang sudah dicatat step `media` (`anime_theme`, tanpa request API): OP pertama entri kanonik, kalau tidak ada OP pertama entri gabungan paling populer, dan kalau show sama sekali tidak punya video OP (kebanyakan movie) ED dengan urutan yang sama. Videonya dibaca **sekali** (maks. 120 dtk), satu frame tiap 2 dtk (`SHOT_FPS`): tiap frame disimpan sebagai WebP lebar 960 dan dinilai oleh **detektor wajah anime** (`pipeline/faces.ts`: model ONNX `deepghs/anime_face_detection` face_detect_v1.4_n, YOLOv8n, MIT, ±12 MB, diunduh sekali ke `data/models`; lewat `onnxruntime-node`). Urutan pilihan: wajah karakter terbesar dulu, lalu (tanpa wajah) yang paling dekat ke detik 45; 5 dtk pertama dilewati, antarscreenshot minimal 8 dtk, dan frame gelap/terlalu terang/datar atau yang **menampilkan judul show** (OCR seperti step `titles`, dicocokkan dengan judul, judul Inggris/Jepang, dan sinonim semua entri show itu; mis. title card "SAKAMOTO DAYS") dilewati → `v1/shot/<hash>.webp`, tabel `anime_screenshot` (slot 0–2). Slot 0 (screenshot pembuka ronde) = wajah terkecil dari ketiganya, slot 2 = terbesar, jadi tiap clue makin membantu. Frame lama (`anime_screenshot.checked_at` NULL, dipilih sebelum ada deteksi wajah) diganti per slot; slot tanpa pengganti tetap memakai frame lamanya (puzzle lama butuh 3 screenshot). Step `daily` juga memproses Guess the Anime hari ini dan besok. Show paling populer dulu (easy, medium, lalu hard untuk ronde 3 harian); satu video 30–60 MB, jadi run terjadwal berhenti setelah 60 menit (`SCREENSHOTS_BUDGET_MS`), kecuali `--limit` diberikan (jumlahnya yang membatasi); run berikutnya melanjutkan |
| `clips` | Clue Opening/Ending sebagai klip kecil: video lagu (versi terkecil di AnimeThemes, `anime_theme.video_url`, dicatat step `media`) di-encode ulang jadi 240p H.264 tanpa suara (±1,3 MB rata-rata, bukan 30–60 MB) → `v1/clip/<hash>.mp4`, kolom `anime_theme.clip_key`. Karena kuota R2 gratis 10 GB, **semua lagu easy + medium** (member entri asal lagu, seperti difficulty lagu di catalog; ±4.500 lagu ≈ 6 GB), entri paling populer dulu; lagu hard tetap di-stream lewat `/api/media`, kecuali lagu ronde harian (step `daily`). Maksimal 60 menit per run (`CLIPS_BUDGET_MS`), kecuali `--limit` yang menentukan jumlahnya; sisanya lanjut di run berikutnya. Klip yang gagal dibuat ditandai `''` dan di-stream juga |
| `titles` | Menyembunyikan **judul anime** yang tampil di video clue OP/ED. **Semua lagu yang bisa diputar** dan belum dipindai (dari klipnya kalau ada, kalau tidak dari video AnimeThemes), entri paling populer dulu supaya lagu easy + medium cepat siap untuk unlimited: **dua frame per detik** (`OCR_FPS`; logo beranimasi hanya terbaca di sebagian frame: OP1 Charlotte cocok di 1 frame pada 1 fps, 3 frame pada 2 fps) di-upscale ke 720p grayscale lalu dibaca OCR (**tesseract.js**, bahasa `eng` + `jpn`, data bahasa diunduh sekali ke `data/tessdata`). Teks tiap frame dicocokkan secara fuzzy dengan judul, judul Inggris, judul Jepang, dan sinonim entri lagu itu dan show-nya (`pipeline/titleText.ts`: huruf dan angka saja, nama Latin < 5 / CJK < 3 karakter dilewati, toleransi 1 salah per 4 karakter Latin / 6 karakter CJK; logo bercahaya terbaca mis. "Charlate" untuk Charlotte). Momen yang cocok ±1,5 dtk → `anime_theme.title_spans` (JSON `[[mulai, akhir], …]`, `[]` = tidak ada judul, `NULL` = belum dipindai; direset kalau audio lagunya berubah). ±70 dtk per lagu, 3 sekaligus, maksimal 60 menit per run (`TITLES_BUDGET_MS`), kecuali `--limit` yang menentukan jumlahnya; sisanya lanjut di run berikutnya. Step `daily` memindai lagu tiap ronde harian juga, dengan atau tanpa klip. OCR hanya membaca judul yang dicetak jelas (mis. "SWORD ART ONLINE", "ソードアート・オンライン"); logo tulisan tangan atau yang sangat bergaya (mis. OP1 OreImo, OP1 Kimetsu no Yaiba) biasanya lolos |
| `catalog` | Selalu ikut di setiap run (sebelum `daily`, yang mengundi dari sini), juga kalau tidak diminta. Menulis **snapshot pool** ke tabel `catalog` (satu baris `shows`: per show kanonik franchise, difficulty, media type, genre, populer, media `shots`/`chars` ok, difficulty karakternya, dan lagu yang bisa diputar dengan difficulty entrinya plus `ready` kalau pipeline sudah selesai dengan clue-nya: sudah dipindai step `titles` dan, kecuali lagu hard, sudah dicoba dibuatkan klip oleh step `clips`; `catalogSong` di `server/catalog.ts`), menulis ulang `completed_shows` (list completed tiap pemain sebagai id show), dan mengunggah **tiga daftar JSON ke R2**: autocomplete judul, autocomplete karakter, dan facets Database (`v1/list/<db>/<nama>/<hash>.json`, `<db>` = hash URL database supaya run lokal tidak menghapus daftar produksi). Baris `lists` menyimpan key-nya; generasi sebelumnya baru dihapus di run berikutnya, jadi URL yang masih di-cache tetap ada |
| `daily` | Menyiapkan Opening/Ending **hari ini dan besok** (UTC+7) sebelum pemain datang: membuat puzzle harian kalau belum ada (tiap ronde menyimpan lagunya di `puzzle_round.theme_id`), menyalin lagu penuh tiap ronde ke R2 **di-encode ulang AAC 112 kb/s** (`v1/song/<hash>.m4a`, ±1,3 MB alih-alih ±3,5 MB rip AnimeThemes; kolom `puzzle_round.audio_key`; nama = hash isi, jadi judul tidak bocor) dan membuat klip clue lagu ronde itu kalau belum ada (lagu mana pun, juga di luar cakupan step `clips`). Pemain lalu streaming dari Cloudflare alih-alih menunggu AnimeThemes. Salinan yang lebih tua dari 7 hari dihapus (kuota R2), ronde tanpa salinan tetap lewat `/api/media`. Dijalankan `.github/workflows/daily.yml` dua kali sehari (00:20 dan 12:20 UTC+7; GitHub kadang menunda/melewatkan jadwal, dan karena besok sudah disiapkan ada banyak waktu cadangan), bisa juga manual; `daily:reroll` ikut menghapus salinan puzzle yang dibuang |
| `cleanup` | Menghapus puzzle unlimited yang tidak pernah diselesaikan siapa pun dan progres tamu (`a:…`) yang belum selesai, setelah 14 hari (`STALE_DAYS`). Tamu baru gratis dibuat (satu per request), jadi tanpa ini tabel `play`/`puzzle` tumbuh selamanya. Play yang selesai, progres akun, dan puzzle harian tidak disentuh |

Bisa dijalankan ulang kapan saja; tidak membuat duplikat. Rate limit: MAL 3 req/dtk, jikan-edge 25 req/10 dtk dan 50 req/menit, AnimeThemes 80 req/menit, dengan retry untuk timeout/429/5xx. Step `media` tidak mengunduh lagu (satu request AnimeThemes per entri MAL); run pertama untuk semua entri makan beberapa jam (rate limit AnimeThemes yang jadi batas).

Step `media`, `characters`, `screenshots`, `clips`, `titles`, dan `daily` butuh binary ffmpeg dari `ffmpeg-static`, yang diunduh install script paket itu. npm baru (runner GitHub) melewati install script yang belum disetujui, jadi `allowScripts` di `package.json` menyetujui `ffmpeg-static` dan `esbuild`. Tanpa binary, pipeline langsung berhenti dengan pesan error; dulu (Okt–Nov 2026) setiap frame, klip, dan lagu gagal satu per satu sebagai `ffmpeg null` sementara run tetap hijau.

Hasil run Okt 2026 (1 pemain, `Velvetaco`): 621 completed + 3.701 populer → 3.842 anime, 78 dikecualikan (49 Hentai/Erotica, 29 belum tayang), **3.764 judul bisa dimainkan**: 537 easy, 888 medium, 2.339 hard. Pool harian (easy + medium) ±1.425 judul.

## Game

- **Difficulty** dari jumlah member MAL: **easy** ≥ 500 rb, **medium** 200–500 rb, **hard** < 200 rb (ambang di `shared/catalog.ts`).
- **URL** bersih (History API, `src/route.ts`): `/`, `/daily`, `/play/<id>`, `/database?…`, `/database/<mal_id>`; link di dalam app pindah halaman tanpa reload (kecuali `/api/*` dan `/oauth/*`, yang memang ke server), back/forward jalan, dan `vercel.json` menyajikan `index.html` untuk path lain (file statis dan API tetap duluan). Link lama `/#/…` otomatis diubah ke path-nya.
- **Harian** (`/daily`, `/daily/opening`, `/daily/ending`, `/daily/character`, `/daily/screenshot`): satu puzzle per mode per tanggal **UTC+7** (ganti hari 00:00 UTC+7, `todayUtc7`; di UI ditulis "UTC+7") untuk semua orang, dipilih deterministik dari pool `semua` (Anidle dan Character: **easy atau medium saja**; Opening, Ending, Guess the Anime: ronde easy, medium, hard), dan tidak mengulang jawaban 60 hari terakhir. Disimpan di DB saat pertama diminta, jadi update pool di tengah hari tidak mengubahnya. Di atas tiap puzzle harian ada bar: "← <hari itu>" kembali ke Home di tanggal yang sama, plus chip lima mode **hari itu** (puzzle arsip tetap di tanggalnya); puzzle unlimited punya "← Unlimited".
- **Difficulty per ronde** (Opening, Ending, Guess the Anime): ronde 1 dari judul **easy**, ronde 2 **medium**, ronde 3 **hard**, untuk harian dan untuk unlimited dengan filter "All"; filter "Easy + Medium" memberi easy, medium, medium (`roundDifficulties` di `shared/modes.ts`). Filter difficulty lain berlaku untuk semua ronde. Kalau slice difficulty itu terlalu kecil (media belum tersalin), ronde itu melebar (`roundTries` di `shared/modes.ts`): ronde 2 dan 3 ke medium + hard, **tidak pernah ke easy**; seluruh pool hanya dipakai kalau pool sama sekali tidak punya judul medium/hard (ronde 1 langsung ke seluruh pool). Di Opening/Ending difficulty-nya milik **lagunya** (member MAL entri asal lagu itu), bukan show-nya.
- **Unlimited** (`/unlimited`): mode harian apa pun, pool `semua`, `teman`, `bareng`, `saya`, atau `populer`, dengan filter genre (18 genre utama) dan difficulty. Pengaturan terakhir diingat browser. URL `/play/<id>` bisa di-reload.
- **Mode beta** (`BETA_MODES` di `shared/modes.ts`; Connections, Synopsis, Higher or Lower, Odd One Out, Timeline): punya menu sendiri, **Beta modes** (`/beta`, sidebar "Free play" dengan tag New, dan tile di Home), dengan pool/genre/difficulty yang sama seperti Unlimited (pengaturan terakhir dipakai bersama; mode dari halaman lain jatuh ke mode pertama halaman ini). Puzzle beta kembali ke "← Beta modes". Label "Beta" di judul game dan dialog **?**. **Hanya unlimited**: tidak ada puzzle harian (400), tidak masuk leaderboard/streak/statistik/`DAILY_MAX_POINTS`. Tanpa tabel baru: Synopsis dan Higher or Lower di `puzzle_round`, Odd One Out dan Timeline di `puzzle_group`. Data yang tidak ada di catalog (sinopsis, skor, tahun) dibaca dari sampel acak pool (batch 40–80 judul), bukan seluruh pool.
  - **Synopsis** (`shared/synopsis.ts`, `server/synopsis.ts`): 3 ronde × 5.000. Ronde diambil bertahap seperti mode ronde lain (`roundDifficulties`/`roundTries`: difficulty All = easy → medium → hard). Sinopsis MAL dipotong per kalimat (maks. 5, minimal 3), judul + nama lain + 10 karakter paling terkenal disamarkan `▇▇▇` (`maskSynopsis`). Kalimat pertama terbuka; clue berikutnya berurutan: kalimat tambahan, lalu fakta (tahun · studio · genre + tag), lalu huruf depan judul (`titleHint`, seperti Guess the Anime). **3 tebakan** per ronde (`SYNOPSIS_GUESSES`): tebakan salah tersimpan di `w` dan ronde tetap terbuka sampai tebakan ketiga. Tiap clue dan tiap tebakan salah −500 (`SYNOPSIS_STEP_COST`), jadi tebakan benar paling sedikit 1.000; salah 3× atau Give up = 0. Setelah ronde selesai, kartu jawaban menampilkan "Also counted as right": entri lain yang juga dihitung benar (season/movie/spin-off yang digabung ke show itu dan show lain se-franchise, urut tahun; `alsoAccepted` di `server/game.ts`, 6 pertama lalu "+N more"). Langkah sama dengan Guess the Anime (`{ round, malId | clue | giveUp }`).
  - **Higher or Lower** (`shared/higherlower.ts`, `server/higherlower.ts`): satu run 21 judul (franchise berbeda, skor MAL bertetangga beda ≥ 0,1). Tebak skor judul berikutnya lebih tinggi/rendah (`{ pick: 'higher' | 'lower' }`); salah sekali = selesai. 500 per tebakan benar, 20 beruntun = 10.000. Skor judul berikutnya baru dikirim setelah ditebak.
  - **Odd One Out** (`shared/oddoneout.ts`, `server/oddoneout.ts`): 5 ronde × 2.000. Lima judul, empat berbagi satu link (data `traits` yang sama dengan Connections, jenis link diundi dulu supaya bervariasi); pilih yang bukan (`{ round, malId }`). Jenis link bisa dipilih seperti Connections (field **Links**, `LINK_MODES`/`usesLinks` di `shared/connections.ts`; `links` di `POST /api/puzzle`, intro game menampilkan "Links in play"). `drawOddRounds` menjamin jawabannya tunggal: membuang judul lain mana pun tidak menyisakan empat judul dengan link bersama.
  - **Timeline** (`shared/timeline.ts`, `server/timeline.ts`): 3 ronde × 5 judul dari tahun berbeda; urutkan dari yang paling dulu tayang dengan ▲▼ lalu kirim sekali (`{ round, order }`). 1.000 per judul di posisi yang benar (maks. 15.000). Tahun baru dikirim setelah ronde dikirim.
- **Connections** (mode `connections`, **beta**: label "Beta" di picker Unlimited, judul game, dan dialog **?**): **hanya unlimited**, tidak ada puzzle harian (`GET /api/puzzle?mode=connections` → 400), tidak masuk leaderboard, streak, statistik riwayat, maupun `DAILY_MAX_POINTS` (`DAILY_MODES`/`isBetaMode` di `shared/modes.ts`). 16 judul dari pool, 4 grup tersembunyi berisi 4 judul yang berbagi satu link: genre, theme, demographic (ditampilkan sebagai **Tags**, mis. "Tags: Shounen"), source, studio, tahun tayang, atau artis OP/ED (`shared/connections.ts`, label di `LINK_KIND_LABELS`). Jenis link bisa dipilih di halaman Beta (field **Links**, semua aktif secara default, minimal satu; disimpan bersama pengaturan lain); dikirim sebagai `links` di `POST /api/puzzle`, disimpan di `puzzle.options`, dan intro game menampilkan "Links in play". Pool yang tidak punya cukup link jenis itu → 404. Grup 1–4 diambil dari tier link (kuning: genre/demographic, hijau: theme/source, biru: studio, ungu: tahun/artis), lalu ke jenis apa pun yang dipilih kalau pool tidak punya. `drawBoard` menjamin link tiap grup **tidak** dimiliki judul lain di papan, jadi solusinya satu; franchise tidak berulang. Link per show ada di baris catalog `'traits'` (step `catalog`, hanya link yang dimiliki ≥ 4 franchise), grup di tabel `puzzle_group`. Tebakan: `POST /api/guess { puzzleId, malIds: [4 id] }`; "One away" kalau 3 dari 4 benar; 4 kesalahan mengakhiri papan. Skor maks **10.000** (tidak ikut total harian): 2.500 per grup yang ketemu (papan selesai atau tidak) −500 per kesalahan, minimal 0 (`connectionsScore`); jadi satu grup tetap bernilai 500 walau kesalahan habis. Link grup baru dikirim setelah grup itu ketemu atau papan selesai. Butuh step `catalog` sudah jalan sekali setelah update ini (kalau belum: 503).
- **Skor**: maksimal per mode berbeda, total 5 puzzle harian = **100.000** sehari (`MODE_MAX_POINTS`, `DAILY_MAX_POINTS` di `shared/modes.ts`): Anidle **10.000** (−500 per percobaan tambahan), Opening dan Ending **15.000** (3 × 5.000, separuh kalau clue dibuka), Character **30.000** (3 × 10.000, 1.250 per nama/anime benar), Guess the Anime **30.000** (3 × 10.000, −2.500 per clue). Tiap ronde bernilai sama (`roundMaxPoints`). Penjelasannya ada di Home ("How scoring works", dilipat) dan di dialog **?** tiap mode (`src/scoring.tsx`, dari konstanta yang sama dengan server). Skor play lama dihitung ulang dengan aturan ini (Nov 2026). Sidebar menampilkan "Today's score" (jumlah skor puzzle harian hari ini) dan skor tiap mode di samping nama mode begitu puzzle harian mode itu selesai (`GET /api/me` → `today.score`, `today.modes`); Home menampilkan skor hari yang dipilih.
- **Arsip**: Home punya pemilih tanggal (← tanggal →, klik tanggal = kalender, "Today") untuk memainkan puzzle harian hari sebelumnya (sejak `FIRST_DAILY_DATE`, 25 Oktober 2026; `GET /api/puzzle?mode=&date=`, puzzle yang belum ada dibuat saat pertama dibuka, tanpa jawaban yang sama dalam ±60 hari). Main ulang hanya untuk seru: leaderboard, streak, dan statistik riwayat hanya menghitung puzzle yang selesai di harinya sendiri (UTC+7).
- **Anidle**: setiap tebakan dibandingkan dengan jawaban: tahun ↑↓, skor ↑↓, source, studio, genre, tags (theme + demographic MAL digabung; cocok/sebagian/beda). **20 percobaan** (`ANIDLE_MAX_GUESSES`; play yang sudah selesai tetap selesai walau batasnya naik); clue terbuka sendiri seiring percobaan bertambah: setelah 12 poster anime-nya (cover) blur, setelah 16 sinopsis MAL (judulnya disamarkan `▇▇▇`, `maskSynopsis`), setelah 19 karakter paling terkenal (maksimal dua), lalu percobaan ke-20 yang terakhir. Tombol **Skip** langsung lompat ke clue berikutnya dan memakai semua percobaan sampai clue itu tanpa menebak (dikonfirmasi dulu; di `play.guesses` tersimpan sebagai `0`, tampil sebagai satu baris "Skipped N tries", di share `⏭️ ×N`). Skor 10.000 − 500 per percobaan tambahan, skip ikut dihitung (500 di percobaan ke-20), 0 kalau tidak tertebak.
- **Opening / Ending**: 3 ronde dari franchise berbeda. Lagu yang diputar dipilih dari **semua OP (atau ED) semua entri MAL** show itu (tabel `anime_theme`; season, movie, dan OVA yang digabung ikut), dan difficulty lagu = difficulty **entri asal lagu itu** (member MAL entri itu, ambang yang sama). Tiap ronde memilih show dulu (pool biasa, filter source/genre/list tetap pada show) di antara show yang punya lagu `ok` dengan difficulty ronde itu, lalu salah satu lagu itu (harian: deterministik dari seed tanggal, unlimited: acak); lagunya disimpan di `puzzle_round.theme_id`. **Unlimited** (juga ganti ronde) mengundi dulu dari lagu yang `ready` di catalog (judul di video sudah dipindai, klip terenkripsi untuk easy + medium) selama show dengan lagu seperti itu minimal 50 dan minimal seperempat slice ronde itu (`READY_MIN_TITLES`, `READY_MIN_SHARE`, `roundPools` di `server/game.ts`), supaya pool yang baru sedikit disiapkan (genre, list kecil, lagu hard selama backfill) tidak mengulang show yang sama; kalau kurang, dari semua lagu. Harian tidak terpengaruh (step `daily` menyiapkan lagunya sendiri). Label difficulty ronde = difficulty lagunya. Lagu diputar **penuh** (bisa di-seek). Puzzle harian: dari salinan R2 yang dibuat step `daily` tiap 00:05 UTC+7 (cepat, CDN Cloudflare); kalau belum ada salinan (unlimited, arsip > 7 hari, atau sebelum step jalan), dari AnimeThemes lewat proxy `GET /api/media?puzzle=&round=&kind=audio|video&v=` (same-origin, jadi nama file AnimeThemes, yang berisi judul anime, tidak terlihat di browser; `v` = tag HMAC dari show dan lagu ronde, berubah kalau ronde diganti). Ketiga lagu diunduh utuh di background begitu puzzle dibuka, ronde langsung tampil dengan "Loading song…"; lagu proxy puzzle harian juga di-cache CDN Vercel (`s-maxage`). **Satu tebakan** per ronde: benar = poin ronde (6.000/7.000/7.000), separuhnya kalau clue dibuka, salah atau "Give up" 0. Jawaban menampilkan judul romaji dan judul Inggris MAL kalau beda (`AnswerInfo.titleEn`, juga di Guess the Anime, Anidle, dan Answers), plus label, judul, dan artis lagunya, dan entri asalnya kalau bukan entri kanonik ("from <season>"). Clue = video OP/ED-nya sendiri, blur dan tanpa suara, **mengikuti lagu** (lagu tidak berhenti saat video memuat; play/pause/seek di player mengatur keduanya, klik video = play/pause, klik dua kali atau tombol Fullscreen = layar penuh, player ikut); Ending juga menampilkan poster (cover) blur di sebelah video. Video selalu lewat `/api/media` (hanya setelah pemain membuka clue): klip 240p di R2 (step `clips` untuk semua lagu easy + medium, dan step `daily` untuk lagu hari itu) kalau ada, diambil server lalu dikirim **terenkripsi** AES-128-CTR (`sealMedia`/`clueKey`, kunci HMAC per puzzle + ronde + lagu, ikut di `clue.key`), kalau tidak video terkecil AnimeThemes di-stream apa adanya dan mulai dimuat dari detik lagu saat itu (`#t=`). Kalau video tidak tampil dalam 20 dtk, clue tinggal cover blur. Kalau lagu gagal dimuat ada "Try again", dan di puzzle unlimited milik sendiri ronde yang belum disentuh bisa diganti (`POST /api/puzzle/replace`: show dan lagu lain dengan difficulty ronde sama).
- **Volume lagu**: satu volume untuk semua lagu (ronde Opening/Ending, Database, review admin), diatur dari slider + tombol mute di sidebar (di HP: bar atas), jadi ada di setiap halaman. Disimpan di `localStorage` (`anidle:volume`, default 70%); mengubah volume di player `<audio>` mana pun juga mengubah volume global (`src/volume.ts`, `src/VolumeControl.tsx`). Video clue tetap tanpa suara.
- **Clue blur**: poster Anidle/Ending blur CSS 4 px di atas file asli. Video clue OP/ED tidak pernah ada di halaman sebagai `<video>`: elemen video dibuat di luar DOM, frame-nya digambar ke `<canvas>` yang sudah blur (`ctx.filter`, `CLUE_BLUR_SHARE` = 1/60 tinggi video: 4 px di klip 240p) dan di rentang `title_spans` (step `titles`) canvas diisi hitam dengan label "Title hidden" sementara lagu tetap jalan (dicek tiap frame dari waktu video; `ClueVideo` di `src/SongGame.tsx`). Klip terenkripsi didekripsi di browser (WebCrypto) ke URL `blob:` yang langsung di-revoke begitu video termuat. Jadi tab Network hanya berisi file acak (`application/octet-stream`), Inspect Element hanya menemukan canvas yang sudah blur (tidak ada filter CSS untuk dimatikan), dan URL `blob:` tidak bisa dibuka di tab lain. Klik kanan dan drag di clue diblokir (`PROTECTED_MEDIA` di `src/App.tsx`; di mobile long-press juga mati lewat CSS). Ini tetap **best effort**: kuncinya ada di respons API dan JavaScript, jadi orang yang membaca kode/debugger tetap bisa mendekripsi; lagu tanpa klip (lagu hard di unlimited, dan lagu easy/medium yang belum dicapai step `clips`) di-stream tanpa enkripsi sehingga URL `/api/media`-nya bisa dibuka langsung. Halaman Database tetap memakai `<video>` dengan blur CSS 6 px (jawabannya memang terlihat di sana).
- **Guess the Anime** (mode `screenshot`): 3 ronde. Mulai dari satu screenshot opening (utuh). Di bawah gambar ada tab clue: "Unlock first clue" (screenshot kedua), "Unlock second clue" (screenshot ketiga), "Unlock title clue" (huruf pertama tiap kata, sisanya `_`, mis. `N_____`; judul Inggris ikut kalau ada), dibuka berurutan kapan saja. Tab screenshot yang sudah terbuka bisa dipilih lagi; petunjuk judul tampil di kotak sendiri di bawah tab, jadi semua screenshot tetap bisa dilihat. **Satu tebakan** per ronde: benar = poin ronde (6.000/7.000/7.000) dikurangi seperempatnya per clue yang dibuka, salah atau "Give up" 0. Clue baru dikirim server setelah dibuka.
- Opening, Ending, Character, dan Screenshot menampilkan "Round N" + label difficulty ronde itu (Easy/Medium/Hard) dari awal; di Character label-nya dari favorit karakternya.
- Setelah puzzle Opening, Ending, Guess the Anime, atau Character selesai, di bawah kartu "Finished" muncul **Answers**: semua ronde sekaligus (Character: semua karakter per ronde) dengan tanda ✓/✗, jawaban benar (link MAL, cover/portrait, lagu untuk OP/ED), pilihan pemain kalau beda (dicoret kalau salah, "also right" kalau show lain yang juga diterima), "You gave up"/"No guess"/"not answered", dan poin per ronde dari maksimalnya (`src/AnswerSummary.tsx`).
- Setiap mode punya tombol **?** di samping judul: dialog "How to play" berisi aturan dan skor mode itu (`src/HowToPlay.tsx`, teksnya dibangun dari konstanta yang sama dengan server: `ROUND_MAX_POINTS`, `ANIDLE_CLUES`, `SONG_CLUE_SHARE`, `SCREENSHOT_CLUE_COST`, …). Escape, tombol tutup, atau klik di luar menutupnya.
- **Character**: 3 ronde × 4 karakter dari 4 anime berbeda (hanya seri TV). Difficulty ronde = popularitas **karakternya** (favorit MAL), bukan animenya: ronde 1 karakter easy, ronde 2 medium, ronde 3 hard (mis. Naruto easy, Rock Lee medium, Chouji hard, semuanya dari anime easy). Anime-nya tetap dari pool biasa (harian: anime easy + medium), dan karakter diambil acak dari karakter show itu yang sesuai difficulty ronde (semua karakter ≥ 50 favorit dari semua entri show itu, tanpa batas jumlah). Per karakter: pilih **nama** dari autocomplete karakter (daftar `characters` di R2, lihat step `catalog`: semua karakter di database, dicari lewat nama atau nickname, romaji saja, tanpa kanji/kana; karakter berbeda dengan nama sama, mis. beberapa "Rin", jadi satu entri, dan kolom nama dinilai dari namanya, bukan id karakter: benar kalau sama dengan nama karakter yang ditanya atau salah satu nickname/alias-nya, jadi memilih karakter lain yang bernama "Kuroneko" tetap benar untuk Ruri Gokou) dan **anime**-nya dari autocomplete judul. Kolom anime benar kalau franchise-nya sama dengan show yang ditanya **atau** karakter itu juga muncul di show yang dipilih (`character_show`; mis. Rin Toosaka dari Fate/Extra juga benar dengan Fate/Zero, Prisma☆Illya, atau Carnival Phantasm). **Satu tombol Guess per ronde**: semua pilihan dikirim sekaligus, kolom yang dikosongkan dihitung salah, dan ronde tidak bisa ditebak ulang. Tiap kolom benar = 1/8 poin ronde (750 di ronde 1, 875 di ronde 2–3). Setelah Guess, tiap kartu menampilkan dua baris hijau/merah (nama, anime) berisi jawaban benar, poin, "Also accepted" (nama: nickname romaji; anime: semua show lain tempat karakter itu muncul, link ke MAL), dan pilihan pemain kalau berbeda (dicoret kalau salah, "also right" kalau nama/show lain yang juga benar); border kartu hijau/kuning/merah.
- Autocomplete menampilkan nama yang cocok dengan ketikan: mengetik "Fate/stay night" menampilkan "Fate - Stay Night → Fate/Zero" (season yang digabung ke show lain), nickname karakter juga begitu. Di **Guess the Anime** autocomplete hanya memakai dua nama lengkap tiap show: judul romaji dan judul Inggris MAL (`TitleEntry.en`), tanpa sinonim/singkatan (SnK, FMA), judul Jepang, atau nama season lain (`fullNamesOnly` di `src/GuessInput.tsx`).
- Semua tebakan (anime dan nama karakter) lewat autocomplete: memilih saran hanya mengisi kolom; tebakan baru dikirim lewat tombol **Guess** (Anidle, Opening, Ending, Screenshot: satu tombol di sebelah kolom, Enter juga bisa; Character: satu tombol untuk seluruh ronde). Mengetik ulang membatalkan pilihan.
- Satu franchise dianggap benar. Jawaban dicek di server dan baru dikirim ke browser setelah game (atau ronde) selesai. Cover jawaban diambil dari R2 kalau sudah disalin, kalau belum dari CDN MAL.
- **Leaderboard** (`/leaderboard`, `GET /api/leaderboard?date=`): skor puzzle harian per tanggal UTC+7 yang diselesaikan di hari itu juga, per mode dan total, hanya akun (pemain anonim tidak punya nama). **Riwayat** (`/riwayat`, `GET /api/history`): per mode jumlah main, persentase tertebak/sempurna, streak harian, rata-rata dan skor terbaik (hanya puzzle harian yang selesai di harinya), plus 60 puzzle terakhir termasuk main ulang arsip (bisa dibuka lagi). **Bagikan hasil**: teks tanpa spoiler ala Wordle (warna per kolom petunjuk / per percobaan ronde), lewat share sheet HP atau clipboard.

## Admin

`/admin` (hanya akun di `ADMIN_USERS`, username akun Anidle): jumlah media per jenis × status (Opening/Ending = jumlah lagu di `anime_theme`), lalu per judul cover, karakter, dan screenshot yang dihasilkan pipeline beserta error-nya, plus **setiap lagu** OP/ED dari semua entri show itu (label, judul, artis, entri asal, audio). **Tolak** membuat media atau lagu itu `rejected`: tidak dipakai puzzle baru dan tidak diproses ulang pipeline (kecuali `--refresh`); **Pulihkan** mengembalikannya ke `ok` (lagu selalu bisa dipulihkan karena di-stream dari AnimeThemes; media R2 hanya kalau file-nya masih ada). File di R2 tidak dihapus. API: `GET /api/admin/media`, `POST /api/admin/media` dengan `{ malId, kind, action }` (media) atau `{ themeId, action }` (lagu).

## Pipeline otomatis (GitHub Actions)

`.github/workflows/pipeline.yml` menjalankan semua step tiap Selasa 03:00 UTC+7 ke Turso + R2 (bisa juga manual lewat **Run workflow**, dengan pilihan step dan flag), dan `.github/workflows/daily.yml` step `daily` tiap hari 00:05 UTC+7. Antrean `enrich_queue` dari "Sinkron ulang" ikut diproses di step `enrich`. Ringkasan run (jumlah per jenis media + daftar media yang rusak di run itu) muncul di halaman run. Secrets yang dibutuhkan: `MAL_CLIENT_ID`, `MAL_CLIENT_SECRET`, `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, `TOKEN_ENC_KEY`, `POOL_USERS`, `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`.

**Kuota Turso**: paket gratis Turso menghitung *rows read* dan *rows written* per bulan kalender, dan kalau habis semua query diblokir (`BLOCKED`, situs mati sampai kuota reset; ini terjadi Okt 2026). Penjaganya:
- **Pool puzzle tidak di-query per puzzle**: pool dibangun di memori dari snapshot `catalog` (1 baris) dan `completed_shows` (1 baris per pemain), lalu difilter persis seperti SQL lama (pool, genre, difficulty, lagu + difficulty entrinya, media, media type). Membuat puzzle dulu membaca 12k–50k baris (unlimited Opening ±50k, Character ±29k), sekarang ±10–100 baris (Character ±700, karena karakter dan petunjuk 12 show dibaca lewat index). Snapshot dibangun ulang step `catalog` di setiap run pipeline; reject/restore admin menambal baris itu langsung (`json_set`/`json_remove`, `setCatalogMedia`/`setCatalogSong`), dan sync MAL/unlink menulis ulang baris `completed_shows` pemain itu.
- **Daftar besar di R2, bukan Turso**: autocomplete judul (±620 KB), karakter (±440 KB), dan facets Database dibaca browser langsung dari R2 (immutable, brotli dari Cloudflare); `GET /api/lists` (1 baris, cache CDN 5 menit) hanya memberi URL terbarunya. Dulu tiap cold start membaca 7,6k (judul), 40k (karakter), dan 68k (facets) baris.
- Query lain di jalur request memakai index: `play(username)` (riwayat, pindah progres tamu saat login), karakter/genre jawaban per puzzle.
- Yang masih membaca banyak disimpan di memori instance function (`server/memo.ts`): baris katalog dan `/api/health` (10 menit), `completed_shows` per pemain (5 menit).
- Route GET yang di-cache CDN menolak parameter yang tidak dipakai (`queryOf` di `server/http.ts`, 400), jadi `?apa=<angka>` tidak bisa melewati cache. `/api/media` hanya melayani URL persis yang diberikan game (`v` harus cocok), mengalihkan (302) ke salinan R2 kalau ada (lagu harian, klip), dan hanya respons 200 utuh lagu harian yang boleh di-cache publik.
- Batas per IP per menit di `api/router.ts` (`server/ratelimit.ts`; dihitung per instance function): buat puzzle 20, ganti ronde 30, login 10, daftar 5, mulai OAuth MAL 10, `/api/media` 60, route lain 180. Batas global sebaiknya juga dipasang di Vercel Firewall.

## Database

Halaman `/database` menampilkan semua judul yang bisa keluar di Anidle (`GET /api/anime`, 48 per halaman; opsi filter dari daftar `facets` di R2, lihat step `catalog`).

- **Sort**: popularity (member terbanyak), skor, tahun terbaru/terlama, judul A–Z.
- **Filter**: cari judul (romaji/Inggris/Jepang/sinonim), genre dan tags (theme + demographic; digabung AND), studio, source, difficulty.
- Kartu menampilkan tahun, skor, member, ranking, jumlah entri yang digabung, plus chip studio, source, genre, dan tag yang bisa diklik untuk menambah filter. Filter tersimpan di URL (`/database?genre=22&sort=score`), jadi bisa dibagikan dan bertahan saat reload.
- Klik cover/judul kartu membuka **detail show** (`/database/<mal_id>`, `GET /api/anime/detail?id=`; id entri mana pun diarahkan ke show-nya): judul Inggris/Jepang, season/tahun, tipe, episode, member, difficulty, chip studio/source/genre/tag (klik = filter list), lalu satu **tab per mode** berisi persis apa yang dipakai game: **Anidle** (6 atribut yang dibandingkan + 3 clue seperti di game: poster blur, sinopsis bertopeng `maskSynopsis`, dua karakter), **Opening/Ending** (semua lagu yang bisa diputar, dari semua entri, urut tanggal tayang entri lalu nomor lagu: judul, label, artis, entri asal, difficulty lagu, audio penuh, dan klip clue blur yang baru dimuat setelah "Show clue"; Ending + poster blur), **Character** (portrait, nama + nickname yang diterima, role, favorit, difficulty karakter, show lain yang juga diterima lewat `character_show`), **Guess the Anime** (3 screenshot + petunjuk judul `titleHint`), **About** (sinopsis lengkap, semua entri MAL yang digabung, sinonim). Tab menandai mode yang memang bisa menanyakan show itu ("asked"; Opening/Ending: jumlah lagunya). Hanya media dan lagu berstatus `ok`. "← Database" kembali ke list dengan filter terakhir.

## Struktur

```
api/        Satu-satunya Vercel Function: router.ts, yang meneruskan setiap /api/* ke routes/
routes/     Handler API (export GET/POST, Web Request/Response), satu file per path: routes/anime/detail.ts = /api/anime/detail
server/     db (libSQL), env, MAL API + OAuth, session/cookie, enkripsi token, logika puzzle
shared/     logika murni + test: aturan pool, normalisasi judul + autocomplete, perbandingan Anidle, franchise
pipeline/   CLI pengisi database + sources/ (jikan-edge) + rate limiter
db/         schema.sql
src/        React app: sidebar (Sidebar.tsx), Beranda (Home.tsx), Anidle.tsx, mode ronde (RoundGame.tsx), Unlimited, Database, Leaderboard, Riwayat (HistoryPage.tsx), Akun & MAL (AccountPage.tsx), Admin (AdminPage.tsx), share.tsx
```

Semua `/api/*` (dan `/oauth/callback`) di-rewrite ke `api/router.ts` oleh `vercel.json`; lokal, plugin di `vite.config.ts` melakukan hal yang sama. Alasannya batas paket Hobby: maksimal 12 Serverless Function per deployment, dan setiap file di `api/` dihitung satu function. Route baru cukup ditambah di `routes/` lalu didaftarkan di `ROUTES` pada `api/router.ts`.
